π0 精读

1. 问题：语义与高频控制之间的鸿沟

2024 年的 VLA（RT-2、OpenVLA 一系）把动作离散成 token 自回归生成——这在语义层面优雅，但在高频灵巧操作上撞墙：离散化有精度损失、逐 token 串行解码慢、自回归的逐点生成难以表达连续轨迹的多模态分布。π0 的判断是：动作应该连续生成，而且要用 DP 已经验证过的“生成式分布表达”，但推理步数要压到高频可用——答案是 flow matching。

2. 架构精读

2.1 双权重块 + 同一序列

π0 = PaliGemma 3B（SigLIP 视觉编码器 + Gemma 语言模型，互联网级预训练）+ 动作专家约 300M（从头初始化），合计 3.3B。关键在交互方式：图像/语言 token 走 VLM 权重，机器人状态与带噪动作 token 走动作专家权重，但所有 token 在同一序列里做联合 attention——论文明确说这是“两个混合元素的 mixture of experts”式设计。动作专家不是接在 VLM 后面的另一个模型，而是同一次前向里并行工作的独立权重块。

2.2 Flow matching 动作块（H=50）

动作块记 $\mathbf{A}^\tau_t = [\mathbf{a}^\tau_t, ..., \mathbf{a}^\tau_{t+H-1}]$，动作地平线 H=50（任务口径 50Hz，约 1 秒的未来动作）。训练时把带噪动作 token 与时间步 $\tau$ 一起塞进序列，只对 H 个动作位置的输出计算流匹配损失：回归直线速度场 $\mathbf{v}_\theta$；推理从噪声沿直线 Euler 积分数步。预训练是 Transfusion 式多目标：机器人数据走 flow matching 损失，图文数据保留语言建模目标——语义能力不掉，动作能力照学。

3. 训练与数据

预训练混合 = 自有灵巧操作数据（7 种机器人构型、68 个任务）+ 完整 OXE 数据集（22 种机器人），总量超过 10,000 小时；再按任务微调。论文强调流匹配给的“高精度 + 多模态建模”正是高频灵巧任务（叠衣服）此前自回归 VLA 做不了的原因。

4. 结果与消融

三组对照值得记住：①π0-small：470M 的无 VLM 初始化消融版——证明“互联网预训练的主干”本身是性能来源，不是参数量的堆砌；②与 OpenVLA / Octo 的“对齐训练量”对比（160k steps，OpenVLA 还额外试了只在目标本体数据上训练的版本），π0 全面占优；③微调效率：叠衣服、收桌子、装盒子等任务上少量演示即可适配。2025 年开源 openpi（JAX/PyTorch 双实现），成为社区最重要的 VLA 基座。

5. 研究者注记

①动作频率 ≠ 推理频率：50Hz 是动作块内动作点的时间参数化，模型重规划频率低得多——块间衔接（RTC/ensembling）是独立的工程问题。②“VLM + 小动作专家 + 分块注意力”是一个可复用骨架：SmolVLA 换成 SmolVLM2 照用，π0.5/π0.6/π0.7 沿用。③flow matching vs 扩散的取舍（直线路径、步数可调、确定性采样）在 DP 页的去噪动画语境下理解最直观：π0 本质上把“扩散的随机游走”换成了“直线流”。
